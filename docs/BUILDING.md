# Building Air Remote

## Pinned toolchain

The Golden Gate Android bindings use an older build stack. Keep these versions together; a newer JDK or Gradle is not a drop-in replacement.

| Component | Version |
| --- | --- |
| JDK | 11 |
| Gradle wrapper | 6.9.1, distribution checksum verified |
| Android Gradle Plugin | 4.1.0 |
| Kotlin | 1.4.31 |
| Android compile SDK | 30 |
| Android target SDK | 36 |
| Android minimum SDK | 31 |
| Android Build Tools | 30.0.2 |
| Android NDK | 23.0.7599858 |
| Android SDK CMake package | 3.10.2.4988404 |
| Native ABI | arm64-v8a |

The app opts into Android 16 runtime behavior while compiling the existing transport APIs against SDK 30. Modernizing the transport build is separate work; changing only version numbers can break its Gradle/native integration.

Install Git, Python 3.9+, JDK 11, and Android command-line tools. Install SDK components using Android Studio's SDK Manager or `sdkmanager`:

```sh
sdkmanager "platforms;android-30" "build-tools;30.0.2" "ndk;23.0.7599858" "cmake;3.10.2.4988404"
```

Recent Android command-line tools may themselves require JDK 17+. Run SDK installation using the JDK required by those tools, then switch `JAVA_HOME` to **JDK 11** for this project's Gradle build. Review and accept the SDK licenses normally.

## Windows PowerShell

Replace these example paths with your own installations:

```powershell
$env:JAVA_HOME = 'C:\path\to\jdk-11'
$env:ANDROID_HOME = 'C:\path\to\Android\Sdk'
python scripts/build.py
```

The scripts derive paths from their own location and the environment. They do not require a specific username, workspace drive, phone serial, or globally installed CMake.
`scripts/build.py` keeps `ANDROID_HOME`, the legacy `ANDROID_SDK_ROOT`, and the project's ignored `local.properties` SDK/NDK entries consistent. Other entries in `local.properties` are preserved. Explicit NDK selection is needed by the legacy bindings during Gradle configuration. If you run Gradle directly, keep the SDK settings consistent yourself.

## Linux or macOS

```sh
export JAVA_HOME=/path/to/jdk-11
export ANDROID_HOME=/path/to/android-sdk
python3 scripts/build.py
```

The same source is intended to build on these hosts. A local Windows build and the repository's CI configuration do not establish that every host environment has been tested.

## Individual steps and Android Studio

```sh
python scripts/bootstrap.py
python scripts/build_native.py --sdk /path/to/android-sdk
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

On Windows use `gradlew.bat`. On Unix, if your checkout does not preserve executable permissions, run `chmod +x gradlew` first.

Run bootstrap and the native build before importing the root folder into Android Studio. Select Gradle JDK 11 and the wrapper. Android Studio may create `local.properties`; it is intentionally ignored by Git. If `local.properties` specifies a different SDK from `ANDROID_HOME`, make them consistent.

The source checkout under `.deps/` is generated. `dependencies.lock.json` pins the exact fork and two native submodules. Bootstrap verifies their revisions and applies one documented local JNI linker setting for 16 KiB page alignment. It does not copy or patch app source into the dependency.

## Install and run

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Use normal Android installation checks and permissions. This project does not require disabling Play Protect. If Android blocks a build, inspect the reason and resolve the build or classification issue.

The application ID is `dev.airremote`. This gives the standalone project its own identity, separate from the earlier prototype. Debug signing keys are generated by the Android tooling and are never committed. Use your own signing process for a public release; debug artifacts are for development and testing.

## Common failures

- **Missing `.deps`**: run `python scripts/bootstrap.py`.
- **Wrong Java version**: check `JAVA_HOME` and `gradlew --version`; the Gradle JVM must be JDK 11.
- **Missing `libgg.so`**: run the native build before Gradle assembles the app.
- **NDK/CMake not found**: verify the exact SDK package versions above and `ANDROID_HOME`.
- **JitPack or Maven unavailable**: dependency resolution needs internet access on the first build.
- **D8 warns that API 31 is unsupported**: the pinned legacy dex compiler emits this warning for the app's minimum SDK. The Windows debug build completes with it; this is a known build-tool limitation, not evidence of wider device compatibility. Modernizing the toolchain remains separate work.
- **Very long Windows paths**: use a short checkout path if CMake/Ninja reports path-length errors.
- **Band busy or command failure**: keep it nearby, confirm pairing and Bluetooth, and allow the service to finish before retrying. See the Google Health limitation in the README.
